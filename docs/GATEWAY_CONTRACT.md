# VN Compliance Gateway Contract

The gateway does not know tax law. It transports canonical statutory objects generated by domain modules.

Every submission must include: Company, submission type, source document references, rule-set/snapshot hash, schema version, payload hash, idempotency key and adapter identity.

Adapter lifecycle:

```text
prepare -> validate -> submit -> get_status -> reconcile
                                  |-> download_receipt
                                  |-> adjust / replace / cancel (when supported)
```

A timeout after `submit` is `UNKNOWN`, not `FAILED`. `UNKNOWN` must call `reconcile`/`get_status` before another submission attempt.

Adapters are capability-based. The core must not assume every tax, BHXH or e-invoice provider supports every operation.
